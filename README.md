# deepseek-tui

A single-binary terminal UI for DeepSeek chat, written in Go. It speaks to the
DeepSeek web backend directly, streams replies into a scrollable viewport, and
solves the `DeepSeekHashV1` proof-of-work challenge natively — no browser, no
WASM runtime, no JavaScript sidecar.

```
◆ deepseek-tui [think] [search]                           ready
────────────────────────────────────────────────────────────────
you
explain the keccak round constants

deepseek
The round constants are generated by an LFSR...
▍
────────────────────────────────────────────────────────────────
› message DeepSeek…
enter send · ctrl+d think · ctrl+s search · ctrl+r chats · ctrl+n new · ctrl+c quit
```

## Features

- Bubble Tea TUI: header status, scrollable chat history, streaming output,
  spinner while connecting, inline proof-of-work progress.
- DeepThink & Web Search Toggles: hotkeys `ctrl+d` (toggle reasoning mode) and
  `ctrl+s` (toggle web search retrieval) with live status badges `[think]` and
  `[search]`.
- Mid-Stream Cancellation: press `esc` during streaming to abort in-flight
  generation immediately without losing prior chat history or exiting.
- Conversation History Export: export entire chat sessions with reasoning blocks
  to clean Markdown using `e` in the recent chats drawer or `--export <id>` via CLI.
- Document & File Attachments: attach local files/documents directly using
  `-f, --file <path>` in CLI or `/file <path> <prompt>` in the TUI input box.
- Dual-mode binary: no arguments opens the TUI; prompt arguments run a
  non-interactive one-shot query, with `-c`/`--code` printing only fenced code
  blocks and `--first`/`--lang` selecting output.
- Pure Go `DeepSeekHashV1` solver: Keccak-f[1600] restricted to rounds 1–23,
  SHA3-style `0x06` padding, 136-byte rate, 32-byte digest, parallel nonce
  search across up to 8 workers.
- Streaming SSE parser that handles both the simple `p`/`o`/`v` patch format
  and the newer fragment/snapshot protocol, including `THINK` fragments.
- Multi-turn sessions with `parent_message_id` tracking and `model_type`
  handling for the first turn.
- Recent-chats drawer: lists the account's server-side sessions, restores a
  selected chat's full history (including reasoning), keeps multi-turn
  continuation working, supports pagination, and can delete a chat with
  confirmation.
- Token discovery from `DEEPSEEK_TOKEN`, then `~/.config/deepseek.token`, with
  a `--token` bypass and an in-TUI token screen that supports typing and
  bracketed paste.
- Tolerant response decoding: flat `{"id": ...}` and the production
  `data.biz_data...` envelope both work.
- Assistant replies rendered as terminal Markdown: headings, emphasis,
  inline code, links, lists and task lists, blockquotes, rules, tables, and
  fenced code blocks that keep their indentation and language tag.

## Requirements

- Go 1.24.2 or newer (dependency floor set by Bubble Tea v1.3.10 / Bubbles v1.0.0).
- A DeepSeek web account token.

## Build

```bash
go build -trimpath -buildvcs=false -ldflags "-s -w" -o deepseek-tui .
```

`-buildvcs=false` keeps VCS metadata (remote path, commit, build time) out of
the binary. Cross-compile with `make cross`; the app is pure Go and
`CGO_ENABLED=0` works for Linux, macOS, and Windows.

## CLI mode

Run with a prompt to use the non-interactive CLI. The answer is streamed to
stdout, thinking is disabled, and errors go to stderr:

```bash
./deepseek-tui "explain the keccak round constants"
```

Pass `-c` (or `--code`) to print only fenced Markdown code blocks. In this
mode the prompt is extended with a short instruction asking for a single
fenced block; pass `--no-hint` to send the prompt unchanged:

```bash
./deepseek-tui -c "write a small Go HTTP server"
```

Select only the first block, or filter by language:

```bash
./deepseek-tui --first "write a shell script" > script.sh
./deepseek-tui --lang bash,sh "write a shell script"
```

Attach a local file or document to the query:

```bash
./deepseek-tui -f /path/to/report.pdf "summarize key points"
```

Export an existing conversation to Markdown:

```bash
./deepseek-tui -e <session-id> > chat.md
```

Control reasoning mode and web search retrieval:

```bash
./deepseek-tui --think "solve this logic puzzle step by step"
./deepseek-tui --no-search "explain quicksort in Go"
```

### CLI flags

| Flag | Description |
| :--- | :--- |
| `-c, --code` | print only fenced Markdown code blocks |
| `-1, --first` | print only the first selected block (implies `--code`) |
| `-l, --lang LANG` | only blocks in LANG, comma-separated (implies `--code`) |
| `-f, --file PATH` | attach a local document or file to the query |
| `-e, --export ID` | export full session history as Markdown to stdout |
| `--no-hint` | send the prompt without the automatic code-only instruction |
| `--think` | enable thinking / reasoning mode (DeepThink) |
| `--no-think` | disable thinking / reasoning mode (default in CLI) |
| `--search` | enable web search retrieval (default) |
| `--no-search` | disable web search retrieval |
| `--serve [ADDR]` | start local OpenAI / Responses / Anthropic API server (default `127.0.0.1:8080`) |
| `--serve-key KEY` | require `Authorization: Bearer KEY` or `X-API-Key` for `--serve` |
| `--token TOKEN` | DeepSeek web userToken (overrides env and config file) |
| `-h, --help` | show usage help and exit |
| `--version` | print version and exit |

`--first` and `--lang` imply `-c`. Language names are matched
case-insensitively; `shell` matches `sh`, `bash`, `zsh`, and `fish`, and common
pairs such as `js`/`javascript`, `py`/`python`, `ts`/`typescript`, and
`golang`/`go` are recognized. If no block is found, or none matches `--lang`,
stdout stays empty and the process exits 3.

Flags may appear before or after the prompt. Use `--` for prompts that start
with a dash. An empty prompt exits with status 0; invalid flags exit with 2.
The token is resolved the same way as in the TUI (`--token`, `DEEPSEEK_TOKEN`,
then the saved token file). A `--token` invocation with no prompt opens the
TUI with that token.

## File attachments & drag-and-drop

Attach documents directly to queries in both TUI and CLI modes:

- **TUI Drag-and-Drop:** Drag any file (`.pdf`, `.txt`, `.md`, `.docx`, etc.) from
  your desktop or file manager directly into the terminal window. The TUI
  automatically normalizes the path, strips quotes and `file://` schemes,
  unescapes characters, and formats the input into `/file <path> `. Press
  `Enter` immediately to analyze it, or type your question after the path.
- **TUI Command:** Type `/file <path> <optional prompt>` in the input box.
- **CLI Mode:** Pass `-f <path> <prompt>`, or simply pass the file path as an
  argument (e.g. `./deepseek-tui ./report.pdf "summarize key points"`).

## API server mode (`--serve`)

Run `deepseek-tui` as a local HTTP server so OpenAI/Anthropic SDKs and coding
agents (OpenCode, Codex CLI, Claude Code, Cline, Roo Code, Aider) can connect
directly without an external proxy:

```bash
./deepseek-tui --serve 8080
# or bind an explicit address and require a local API key:
./deepseek-tui --serve 127.0.0.1:8080 --serve-key "local-secret"
```

Bare ports bind to `127.0.0.1` by default. `DEEPSEEK_SERVE_KEY` can also be
used instead of `--serve-key`.

### Supported endpoints

- `GET /health` (`GET /healthz`) — liveness check (`{"status":"ok"}`)
- `GET /v1/models` — lists `deepseek-chat`, `deepseek-reasoner`,
  `deepseek-chat-search`, and `deepseek-reasoner-search`
- `POST /v1/chat/completions` — OpenAI Chat Completions API (streaming SSE and
  non-streaming JSON, `tools`/`functions`, `tool_choice`, `reasoning_content`,
  `stop`, `stream_options.include_usage`, `web_search_options`)
- `POST /v1/responses` — OpenAI Responses API (flattened `tools`,
  `instructions`, `input` items, `previous_response_id`, streaming SSE events)
- `POST /v1/messages` — Anthropic Messages API (`x-api-key`, `system`,
  `input_schema` tools, `tool_use`/`tool_result` blocks, `thinking`, SSE events)

### Tool calling & single-session continuity

Because DeepSeek's web backend has no native `tools` field, `--serve` injects
available tool schemas into the prompt and parses both `<tool_call>` JSON
blocks and DeepSeek's native DSML tags (`<｜DSML｜...>` / `<｜｜DSML｜｜...>`)
across split SSE chunks, emitting standard `tool_calls` / `function_call` /
`tool_use` payloads.

A prefix-matched in-memory session cache (`serveSessionCache`, plus
`previous_response_id` state) tracks `(model, tools, messages[:k])` so
multi-turn tool-calling loops stay inside the same server-side
`chat_session_id` via `parent_message_id` instead of opening a new DeepSeek
chat on every turn.

### Example: OpenCode (`opencode.json`)

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepseek-local": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "DeepSeek Local",
      "options": {
        "baseURL": "http://127.0.0.1:8080/v1",
        "apiKey": "local"
      },
      "models": {
        "deepseek-chat": { "name": "DeepSeek Chat", "tools": true, "reasoning": false },
        "deepseek-reasoner": { "name": "DeepSeek Reasoner", "tools": true, "reasoning": true }
      }
    }
  }
}
```

## Token

The app reads the token in this order:

1. `--token` flag.
2. `DEEPSEEK_TOKEN` environment variable.
3. `~/.config/deepseek.token`.
4. The token screen inside the TUI. Input is masked with dots by default,
   supports normal typing and bracketed paste (`ctrl+v` or right-click),
   and saves to `~/.config/deepseek.token` with mode `0600` on enter.
   Press `ctrl+r` on that screen to reveal the token; press it again to
   hide it.

Grab the value from the web client: open `https://chat.deepseek.com`, open
DevTools → Application → Local Storage → `userToken`, and copy the value.
A leading `Bearer ` prefix is stripped automatically.

```bash
export DEEPSEEK_TOKEN="..."
./deepseek-tui
```

Or skip the token screen entirely:

```bash
./deepseek-tui --token "..."
```

`ctrl+t` reopens the token screen inside a running session. Input is masked
by default; `ctrl+r` on the token screen shows or hides it.

## Keys

| Key | Action |
| --- | --- |
| `enter` | send the current message / save the token / open the selected chat |
| `ctrl+d` | toggle DeepThink reasoning mode (`[think]` / `[think:off]`) |
| `ctrl+s` | toggle Web Search retrieval (`[search]` / `[search:off]`) |
| `esc` | stop/cancel active streaming response / close recent chats |
| `ctrl+r` | open recent chats drawer |
| `ctrl+n` | start a new chat session |
| `ctrl+t` | change the DeepSeek token |
| `pgup` / `pgdown` | scroll history (chat) / move by a page (recent chats) |
| `up` / `down` | scroll history (chat) / select a chat (recent chats) |
| `home` / `end` | jump to top / bottom (chat) / first / last chat (recent chats) |
| `ctrl+c` | quit |

Inside recent chats: `e` exports the chat to a local `./<title>.md` Markdown file, `r` refreshes the list, `l` loads the next page, `n` starts a new chat, and `d` deletes the selected chat after `y` confirmation.

Attaching files: drag and drop any file directly into the terminal window, or type `/file <path> <optional prompt>` to upload and attach a local document to your message.

On the token screen, `ctrl+r` toggles between masked and visible input.

## API flow

1. `POST /api/v0/chat_session/create` with `{"agent":"chat"}` → session id.
2. `POST /api/v0/chat/create_pow_challenge` with
   `{"target_path":"/api/v0/chat/completion"}` (or `/api/v0/file/upload_file`
   for file attachments) → salt, `expire_at`, difficulty, challenge digest, signature.
3. Solve: brute-force nonce in `[0, difficulty)` until
   `DeepSeekHashV1(salt + "_" + expire_at + "_" + nonce) == challenge`.
4. Build the base64 JSON response with `algorithm`, `challenge`, `salt`,
   `answer`, `signature`, and `target_path`; send it as `x-ds-pow-response`.
5. For file attachments: `POST /api/v0/file/upload_file` with multipart form-data
   and `x-ds-pow-response` header → file id.
6. `POST /api/v0/chat/completion` with session id, prompt, populated `ref_file_ids`,
   and thinking/search enabled.
7. Parse the SSE stream. `THINK` fragments render dim and italic; `RESPONSE`
   fragments render as the assistant reply. `response_message_id` from the
   `ready` event becomes the next turn's `parent_message_id`.

Recent chats use three additional web endpoints:

- `GET /api/v0/chat_session/fetch_page?count=50` — newest sessions first;
  follow `has_more` with `lte_cursor.pinned` and `lte_cursor.updated_at` for
  older pages.
- `GET /api/v0/chat/history_messages?chat_session_id=<id>` — the complete
  message list plus `chat_session.current_message_id`, which becomes the next
  turn's `parent_message_id`. Both payload shapes are supported: text in
  `fragments[]` (`REQUEST` / `THINK` / `RESPONSE`) and text in top-level
  `content` / `thinking_content`.
- `POST /api/v0/chat_session/delete` with `{"chat_session_id":"<id>"}`.

The browser headers (`x-client-version`, `x-client-platform`, bundle id,
locale, timezone offset, device id, Firefox user agent) are set on every
request to match the web client. Identity values are per install and derived
at startup:

- `x-device-id` is a UUIDv4 generated on first run and stored at
  `~/.config/deepseek.device` with mode `0600`. Set `DEEPSEEK_DEVICE_ID` to
  override it.
- `x-client-locale` comes from `LC_ALL`, `LC_MESSAGES`, or `LANG`, normalized
  to the `xx_YY` form; `en_US` is the fallback.
- `x-client-timezone-offset` is the current OS UTC offset in seconds.
- `User-Agent` matches the build platform. Set `DEEPSEEK_USER_AGENT` to
  override it.

No device id, locale, timezone, or user agent is baked into the executable.

## Rendering

Assistant replies are parsed as Markdown and laid out for the current
viewport width. Code fences preserve indentation and tabs, show their
language tag, and truncate overlong lines instead of reflowing them. Tables
are drawn with box borders and fall back to compact rows on narrow terminals.
Inline styles are applied after wrapping, so ANSI color codes never break the
layout.

Control characters are stripped before rendering, so model output cannot
inject terminal escapes. Syntax highlighting inside code blocks is not
implemented; images and raw HTML are shown as text.

## Proof-of-work details

`DeepSeekHashV1` is not SHA3-256 and not standard Keccak-256. The permutation
is Keccak-f[1600] starting at round constant index 1 and ending at index 23 —
23 rounds instead of 24. Padding is SHA3's `0x06 ... 0x80`, not Keccak's
`0x01`. The rate is 136 bytes and the digest is the first 32 bytes of the
state, little-endian lanes.

All nonce inputs (`prefix + decimal nonce`) fit inside a single rate block, so
each candidate costs exactly one permutation. The solver copies a pre-filled
base block, appends the nonce digits, applies padding, and compares the digest.
Work is claimed in 1024-nonce chunks by parallel workers with an atomic counter;
the first match cancels the rest.

The test suite pins two `(salt, expire_at, answer)` triples captured from the
live web client, plus their digests:

```
a40318e6b7af56bf27cf_1790959021012_58595
  → 168efa309e5a73033fc82dde4333bbc6515da440ef961574f73f99cbe7b397ad
0b846826f9b7ab6000f6_1790959592240_44460
  → ab9178c48249ac301272e3e24b9a5aef207e593add3003bfd7a8fb8abb572079
```

## Layout

```
main.go             Bubble Tea model/update/view, auth, CLI mode, entry point
server.go           --serve HTTP server, OpenAI Chat Completions, tool parser, session cache
server_protocols.go OpenAI Responses (/v1/responses) & Anthropic Messages (/v1/messages) adapters
markdown.go         Markdown parser, tables, code fences, styled wrapping, render cache
clientenv.go        per-install device id, locale, timezone, user agent, private files
api.go              HTTP client, envelopes, PoW response header, SSE parser
pow.go              Keccak-f[1600] 23-round permutation, DeepSeekHashV1, solver
test/*_test.go      captured hash vectors, solver, envelope shapes, SSE & server protocols
```

## CI and releases

`.github/workflows/ci.yml` runs `go mod tidy`, `go vet`, `go test -race`, a
`CGO_ENABLED=0` build, and a `--version` smoke test on every push and pull
request. Pushing a `v*` tag publishes Linux (amd64/arm64), macOS (amd64/arm64),
and Windows (amd64) binaries plus `checksums.txt` to a GitHub release. Release
notes come from the matching section of `CHANGELOG.md`, falling back to
GitHub's generated notes when no section exists.

## Withdrawn releases

The `v0.1.0` through `v0.3.0` releases were withdrawn and their GitHub
releases and tags deleted on 2026-11-17. Those binaries embedded a shared
device id and fixed locale, timezone, and user-agent values, so every
installation presented the same client identity.

`v0.3.1` introduced per-install identity and was removed when `v0.4.0`
shipped. Its identity fixes are included in `v0.4.0` and later. On 2026-11-17
the repository history was rewritten and force-pushed to purge the embedded
identifier from every commit. Build only from `v0.4.0` or newer; if you have an
older clone, re-clone it.
